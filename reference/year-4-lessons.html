121 What a desk data set is

Teach this one skill: Name the tables a long-only desk must have, and the as-of key that makes each join legal.

What has to be taught, in order:

  1. Everyday picture: a vendor is a company that sells facts about stocks. You do not get 'the truth.' You get files with timestamps.
  2. The store, in plain words: (1) prices and corporate actions, (2) who was in the universe that morning, (3) company facts as they were known then, (4) earnings/news times, (5) how much each name traded (ADV, spread), (6) the benchmark's membership.
  3. An as-of key is the pair (name, morning) that every join must respect. No as-of key ⇒ no honest backtest.
  4. Snapshot vs event: a snapshot is 'as of this morning, this was the row.' An event is 'at 16:05 this print hit the tape.' Both are required. Mixing them is a leak.
  5. This quarter is Year 4 Q1 — the data kit. The rest of Years 4–5 use this store. You do not start a long-only backtest until unit 130 is green.
Trap to teach, not a footnote. A folder of CSVs with no as-of dates, treated as a database.

122 Building a price panel: splits, dividends, delist returns

Teach this one skill: Write the adjuster that turns a vendor close into the holder's wealth, including the last day of a dead name.

What has to be taught, in order:

  1. This is the standing adjuster. Unit 133 will use it as the return you actually earn; do not rebuild a private price file later.
  2. Backward split adjustment: multiply past prices so the series does not jump when the split hits.
  3. Dividends in the same units as the adjusted price. Delist terminal return stays in the panel.
  4. Vendor differences: some files are already split-adjusted and not dividend-adjusted. Teach 'read the flag' as a skill.
Trap to teach, not a footnote. Trusting a column named 'adjusted close' without reading whether dividends are in it.

123 Point-in-time membership

Teach this one skill: Answer 'was this name in my universe on this morning?' from add/drop events, not from today's list.

What has to be taught, in order:

  1. Unit 132 as a table: date × name → in or out. IPOs, index adds, index drops, delists.
  2. Survivors-only vs PIT, again, because this is the store every later lesson will query.
  3. A reconstitution calendar is part of membership, not a surprise in 128.
Trap to teach, not a footnote. Downloading 'current S&P names' and filling ten years backward (132's trap, now as a failing unit test on the store).

124 Point-in-time fundamentals (vintages)

Teach this one skill: Join company facts by what was known that morning, using a vintage / as-of table.

What has to be taught, in order:

  1. A vintage is 'this is the earnings number as it stood on date D.' Later restatements create a new vintage, they do not rewrite D.
  2. As-of join: for each (name, morning), take the latest vintage with release time ≤ that morning.
  3. Restated join (the leak): paste the final 10-K onto the whole year. Plant it. Catch it.
  4. Fiscal vs calendar periods. Point-in-time is about the release clock, not the fiscal label.
Trap to teach, not a footnote. A fundamentals table keyed only by fiscal year.

125 Earnings and event calendar as a first-class table

Teach this one skill: Store announce time (not just date), surprise, and whether the print was before the open or after the close.

What has to be taught, in order:

  1. Required columns: name, timestamp (timezone named), period, surprise definition, source.
  2. After-close vs before-open. Unit 176's leak is a failing test here.
  3. Revisions and upgrades can live in the same event store with a type flag.
Trap to teach, not a footnote. A calendar of 'earnings dates' with no timestamps and no timezone.

126 Daily bars: open, close, auction, VWAP, volume, spread

Teach this one skill: Build one row per name per day that a daily book can actually use, and say how each field was made.

What has to be taught, in order:

127 Liquidity history: ADV, spread, days-to-trade

Teach this one skill: Store a trailing ADV and a days-to-trade at your intended participation, as-of each morning.

What has to be taught, in order:

  2. Days-to-trade at 3% participation for a stated AUM. This number feeds 173 and 192.

131 The long-only mid-horizon mandate

Teach this one skill: State the job in one sentence, and keep score with information ratio, not Sharpe.

What has to be taught, in order:

  1. Everyday picture: you own a shopping cart of stocks for weeks to months; you never borrow shares to bet they fall. That is long-only.
  2. Name the benchmark — the comparison basket you claim to beat (often the same stocks, cap-weighted). Without a named benchmark the exam is undefined.
  3. Active return is your return minus the benchmark's return. Tiny numbers: index +10%, you +12% → active return = +2%.
  4. Tracking error is how much that extra piece bounces (the volatility of active return).
  5. Information ratio (IR) = active return ÷ tracking error. That is the exam. Sharpe = extra return over cash ÷ how hard the whole book bounces — a long-only book can look fine on Sharpe just by riding the market tide (beta).
  6. Contrast with the Q1 lab: that book was dollar-neutral (dollars long ≈ dollars short). This book is allowed to go up and down with the market. Teach when each exam is the honest one.
  7. This clock is weeks-to-months. Lesson 001 called it low frequency / factor investing, not mid-frequency (hours–days).
Trap to teach, not a footnote. Treating a long-only Sharpe as proof of skill. Most of that number is beta. The lesson must compute both IR and Sharpe on the same toy book.

132 Universe construction without quietly dropping losers

Teach this one skill: Build the list of stocks you are allowed to own as of this morning, not as of today looking backward.

What has to be taught, in order:

  1. A universe is the list of names the book may hold. It changes: companies list (IPO), leave, go bankrupt, get bought.
  2. Point-in-time means using only what a researcher could have known on that morning. The opposite is peeking at who survived until now.
  3. Survivorship bias is the lie you get by studying only the names still alive. Dead names were often the losers; dropping them makes any rule look better.
  4. Teach the two rebuilds side by side: survivors-only vs point-in-time membership. The gap is the fake premium.
  5. IPOs: a name must not appear before its first trade date. Delistings: the last day still has a return (often ugly). Missing days are not 'drop the row.'
Trap to teach, not a footnote. Building the universe from today's index members and filling history backward. That is the default vendor download, and it is wrong.

133 The return you actually earn: splits, dividends, delistings

Teach this one skill: Turn a vendor price file into the money a holder of the shares would have made.

What has to be taught, in order:

  1. A split is the company cutting each share into pieces (2-for-1: you have twice as many, each worth about half). The raw price jumps; your wealth does not.
  2. A dividend is cash the company pays you for holding the share. The price often drops by about that cash; you still received it.
  3. Price return ignores dividends. Total return includes them. A backtest on raw prices will lie — usually by looking too good on names that never paid you cash, or too jumpy on split days.
  4. Delist / bankruptcy: the last return is part of the record. Dropping the name the day before the crash is another survivorship lie.
  5. Spinoffs and special dividends: same idea — adjust so the series is the holder's wealth, not the ticker print.
Trap to teach, not a footnote. A price-only backtest on unadjusted closes. Teach it as a planted lie: same rule, two panels, two Sharpes.

134 The cross-section as the unit of observation

Teach this one skill: Ask 'who beats whom next month?' not 'does this one ticker go up?'

What has to be taught, in order:

  1. A characteristic is a number about a stock today (how cheap, how profitable, how much it already went up).
  2. The cross-section is the slice across names at one date: 500 numbers today, not 10 years of one name.
  3. Residual return is the part of a name's move left after you subtract the market tide (and, later, industry). That is what a ranker is trying to forecast.
  4. Fama–MacBeth in plain words: each month, draw the line 'next month's residual vs today's characteristic'; then average those monthly slopes and ask if the average is noise.
  5. One tiny worked slope: 3 names, characteristic 1 / 2 / 3, next residual −1 / 0 / +1 → the line slants up. That is a positive slope, not a trading rule yet.
Trap to teach, not a footnote. Pooling every name-day into one giant regression and quoting a t-stat as if you had 100,000 independent bets. You had ~120 months. Unit 009 already warned; teach it again on this object.

135 Classic baseline I — momentum (12-1)

Teach this one skill: Build the 12-1 winner list, long-only, and say what you lose by not shorting losers.

What has to be taught, in order:

  1. Everyday idea: names that have been winning for a while often keep winning for a few more months.
  2. 12-1 momentum: look at the last 12 months of return, drop the most recent month (that month is often a bounce, not a trend), rank names, own the top group.
  3. Why skip last month: short-horizon reversal (Year 5) lives there. Mixing it in muddies the baseline.
  4. Show long-only deciles and the long-short (own winners, short losers). The short side is often half the old academic story. A long-only book only gets the winner half.
  5. Time-series trend (own it vs cash if the name itself is up) is a different rule. Name the difference; do not mix the labels.
Trap to teach, not a footnote. Calling any 'what went up, buy it' rule momentum. 12-1, 1-month reversal, and time-series trend are three jobs.

136 Classic baseline II — value, and value plus momentum

Teach this one skill: Define cheap vs expensive with a point-in-time ratio, then combine it with 12-1 without peeking.

What has to be taught, in order:

  1. Everyday idea: a cheap name is one whose price is small compared with something real about the company (book equity, earnings). Value is that comparison.
  2. Book/price and earnings/price: define each in words, then as a ratio. The ratio must use the book or earnings that was known that morning (unit 132 / later 124).
  3. Fama–French as the baseline you must beat or own honestly — not as a religion. Size (small vs large) sits next to value; teach it as a characteristic, not a vibe.
  4. Value and momentum often hedge each other (when one is ugly the other is less ugly). A 50/50 and an IC-weighted blend are two different combines; teach both.
Trap to teach, not a footnote. Using this year's 10-K earnings in a 2014 characteristic. That is restatement leakage; it belongs in the same breath as the ratio.

137 Classic baseline III — quality, investment, low-volatility

Teach this one skill: Add profitability and calmness as characteristics, and show that low-vol is often a hidden beta bet.

What has to be taught, in order:

  1. Quality / profitability: highly profitable, conservative firms. Novy-Marx: gross profit as a characteristic, not a slogan.
  2. Investment (Fama–French five-factor): firms that are pouring money into expansion have historically paid less. Teach the characteristic, then the story, in that order.
  3. Low-volatility: the calmest names have historically paid almost as much as jumpy ones. That is a puzzle, not a free lunch.
  4. Neutralize beta (strip the market tide from the score). After that, a lot of the low-vol 'edge' shrinks. The lesson must show the before/after.
Trap to teach, not a footnote. Selling low-vol as alpha when the book is just refusing to own high-beta names. Unhedged, you are underweight the market in a specific way.

138 The factor zoo and publication decay

Teach this one skill: Treat a pile of characteristics as a multiple-testing problem, and expect published edges to shrink.

What has to be taught, in order:

  1. Re-warm Harvey–Liu–Zhu (unit 007): if you search 20 characteristics and keep the winner, the t-stat is a max, not a single test.
  2. McLean–Pontiff: after a paper comes out, the edge often fades. Crowding and data-mining both do this; teach both stories.
  3. Hou–Xue–Zhang: most 'anomalies' do not replicate under one common protocol. The zoo is not a menu of free edges.
  4. Bonferroni and Benjamini–Hochberg on the same 20-characteristic screen. They will disagree; teach what each is promising.
Trap to teach, not a footnote. Keeping a characteristic because the story is pretty after you saw the t-stat. Pre-commit the list (unit 167 will make this a habit).

139 The benchmark you claim to beat

Teach this one skill: Build the index you will be judged against, and show why beating equal-weight is the easier exam.

What has to be taught, in order:

  1. Cap-weight vs equal-weight: in cap-weight, bigger companies are a bigger slice. In equal-weight, every name is the same size (you rebalance to keep it that way).
  2. Reconstitution: the index committee (or rule) adds and drops names on known dates. Your universe and your benchmark must use the same as-of membership.
  3. Float: not every share can trade (insiders, governments). A real cap-weight index uses shares that can trade.
  4. Sharpe's arithmetic: after fees, beating the cap-weight market is a zero-sum exam among active managers. Teach why 'I beat the equal-weight basket' is a different, usually easier, claim.
Trap to teach, not a footnote. Backtesting against equal-weight and quoting the result as if you beat the S&P 500.

141 The monthly prediction target

Teach this one skill: Pick one number the model is trying to forecast, and say why the other two are different jobs.

What has to be taught, in order:

  1. Three candidates: next-month residual return; next-month rank (who beats whom); next-month excess vs the benchmark.
  2. Triple-barrier (unit 035) is a path-dependent label for a trade. A monthly residual is a simpler label that matches a monthly rebalance. Teach the contrast; do not throw AFML away.
  3. Gu–Kelly–Xiu as the paper that already ran 'ML vs linear' on monthly characteristics. This year must beat or honestly match that kind of baseline, not invent a new exam.
  4. A target that includes next month's market tide will teach the model to forecast beta. Residualize first if the mandate is 'who beats whom.'
Trap to teach, not a footnote. Training on next-month raw return and then being surprised the model just bought high-beta names.

142 Point-in-time features — no restated numbers

Teach this one skill: Build a feature table whose every cell could have been known that morning.

What has to be taught, in order:

  1. Features at this clock: lagged returns, size, value ratios, revisions, industry. Each one gets an as-of rule.
  2. Restated fundamentals: the company later changes last year's earnings. A leaked join pastes the new number onto old dates.
  3. Plant the leak on purpose (CCC-style restatement) and catch it with a vintage table: what was on the tape as of date D.
  4. Industry and country are characteristics too; they must be as-of (reclassifications happen).
Trap to teach, not a footnote. A 'fundamentals' CSV with one row per name per year and no vintage date. That file cannot support an honest join.

143 Information coefficient and matching the rebalance to the decay

Teach this one skill: Measure how well today's scores line up with future residuals, and pick a hold that matches how fast that line dies.

What has to be taught, in order:

  1. Information coefficient (IC): correlation between today's scores and next period's residual returns. High IC means the ranking is informative, not that you have a book yet.
  2. IC by holding week 1, 2, … 8. The decay tells you whether monthly rebalance is too slow or too fast for this score.
  3. Re-warm the Fundamental Law (unit 084): IR ≈ IC × √breadth × transfer coefficient. Breadth here is ~N names per month, not 10,000 name-days.
  4. A score that dies in five days does not belong in a monthly book (send it to Year 5). A score that is still alive at week 8 can sit still.
Trap to teach, not a footnote. Rebalancing monthly because 'that is what factor funds do' while the IC is already dead by week two.

144 Linear cross-sectional models

Teach this one skill: Fit a monthly line, after stripping industry, size, and beta from the features.

What has to be taught, in order:

  1. Weighted least squares in one sentence: names with noisier residuals get less pull on the line.
  2. Industry neutralization: subtract the industry average from the feature (or from the residual) so you are not just buying 'all tech.'
  3. Residualizing size and beta: the leftover characteristic is what is not already 'it is a small name' or 'it rides the market.'
  4. This linear model is the thing the tree model in 145 must beat. Teach it as a respected baseline, not a straw man.
Trap to teach, not a footnote. A pooled OLS on the stacked panel with i.i.d. standard errors. The t-stat is a toy.

145 Trees on the monthly cross-section

Teach this one skill: Train a gradient-boosted tree as a regressor and as a ranker, with a walk-forward that does not peek.

What has to be taught, in order:

  1. Re-warm unit 047: a tree asks a sequence of yes/no questions about features. Boosting adds many small trees.
  2. Regressor vs ranker: MSE tries to hit the exact residual; a rank objective tries to get the order of names right. The mandate is closer to order.
  3. Walk-forward year-blocks: train on years 1–7, test 8; then 1–8, test 9. No i.i.d. K-fold.
  4. Gu–Kelly–Xiu: trees helped on monthly characteristics versus a linear model. Teach what they actually did, including the failures.
Trap to teach, not a footnote. Tuning hyperparameters on the same years you will quote as out-of-sample (unit 048, again).

146 Learning-to-rank for 'who beats whom'

Teach this one skill: State pairwise and listwise losses as 'punish a wrong order,' and compare them to MSE on the same panel.

What has to be taught, in order:

  1. Pairwise: for two names, was the one we liked more actually better next month? A loss that cares about that pair.
  2. Listwise: the whole day's ranking is one object. LambdaMART / LightGBM rank as the practical tool.
  3. Top-decile IR is the mandate-shaped metric: we only own the names we like most. A model that is great in the middle and wrong at the top is useless here.
  4. This is still a score. Holdings come later (151–160).
Trap to teach, not a footnote. Optimizing MSE and then being surprised the top 50 names are a mess.

147 Cross-sectional CV that respects time and names

Teach this one skill: Show that ordinary K-fold leaks, and replace it with purged year-blocks.

What has to be taught, in order:

  1. Re-warm AFML 7: overlapping labels and a shared market day mean random K-fold trains on the future.
  2. A second leak: the same firm in train and test across a split that ignores time.
  3. Walk-forward year-blocks vs i.i.d. K-fold on the same features. The fake lift is the lesson.
  4. Embargo: leave a gap after the train window so the last training residual does not share a path with the first test residual.
Trap to teach, not a footnote. Purging days but not embargoing the residual overlap. The leak is quieter, not gone.

148 Combining ML scores with classic factors

Teach this one skill: Measure incremental IR: what the blend adds after 12-1 and value are already in the book.

What has to be taught, in order:

  2. A blend of linear + GBDT + 12-1. The question is not 'is the blend's IR high?' It is 'did the tree add anything the 12-1 did not already give?'

Trap to teach, not a footnote. Reporting the blend's raw IR and calling the tree a win when it is 12-1 in costume (Year 5 unit 189 is the daily twin).

149 When ML adds nothing

Teach this one skill: Kill your own monthly model on a holdout and write the autopsy.

What has to be taught, in order:

  1. Small monthly samples: 10 years × 12 = 120 fits. A flexible tree can memorize regimes.
  2. Regime breaks: a rule that worked in 1995–2007 can die after. McLean–Pontiff again.
  3. Feature death: a characteristic that was informative becomes crowded. The model will not announce this; the IC will.
  4. The required artifact is a written autopsy, not a quieter chart.
Trap to teach, not a footnote. Retraining until the holdout looks good. That holdout is then gone.

151 From score to weight without an optimizer

Teach this one skill: Turn a ranking into holdings three simple ways, and see what an optimizer will later be asked to beat.

What has to be taught, in order:

  1. Top-N: own the N names you like most, equal weight. Everyday shopping cart.
  2. Quantile tilt: own more of the top fifth, less (or none) of the bottom fifth, still long-only.
  3. Rank-weight / z-score tilt: size the name by how strong the score is, then clip negatives to zero if you cannot short.
  4. Compare turnover and IR of these three to the same-score long-short book. The gap is the long-only tax (153 will name it transfer coefficient).
Trap to teach, not a footnote. Jumping to a quadratic program before the learner can do top-N by hand.

152 Active weights and the one-period utility

Teach this one skill: Write 'like more of this, minus risk, minus costs' as a function, then solve a 10-name toy by hand and as a QP.

What has to be taught, in order:

  1. Active weight is how much more (or less) of a name you own than the benchmark does. If the index is 2% of AAA and you own 5%, active weight is +3%.
  2. One-period utility in words: expected extra return − λ × risk − costs. λ is how much you hate being different from the index (or how much you hate bounce).
  3. The 10-name toy: write the numbers, take the derivative or complete the square, get the weights. Then show the same answer from a quadratic program.
  4. Re-warm Markowitz (081): unconstrained MVO is brittle. That is why 154–159 exist.
Trap to teach, not a footnote. Maximizing expected return with no risk term and calling it optimization. That is 'buy the highest score until the money is gone.'

153 Long-only as a constraint

Teach this one skill: Show the optimizer clipping negative weights, and measure what you lose versus long-short (transfer coefficient).

What has to be taught, in order:

  1. A constraint is a rule the holdings must obey. 'No negative weights' is the long-only rule.
  2. When the unconstrained solution wants to short a name, the constrained solution sets that weight to 0 and dumps the leftover into other names. The book is no longer the score.
  3. Transfer coefficient: how much of the score's ranking survived the rules. 1 means the book matches the score; 0 means the rules ate the idea.
  4. Same alpha, three mandates: long-only, long-short, 140/30 (a little short sleeve). Teach 140/30 as an overlay, not the default.
Trap to teach, not a footnote. Reporting the unconstrained IR as if it were the long-only book.

154 Risk models the optimizer trusts

Teach this one skill: Plug three risk models into the same utility and compare promised active risk to realized tracking error.

What has to be taught, in order:

  1. The optimizer needs a forecast of how names bounce together. That forecast is the risk model.
  2. Three families: fundamental (Barra-style: industry + style factors), statistical (PCA / shrinkage from 082), and a naive sample covariance.
  3. Promised active risk vs realized tracking error. A model that is always '2% active risk' and delivers 6% is not conservative — it is wrong.
  4. Re-warm 082–083: cleaned covariance is a risk input, not a trading rule.
Trap to teach, not a footnote. Using a 500-name sample covariance with 12 months of daily data and trusting the optimizer's risk number.

155 Linear constraints real books have

Teach this one skill: Add sector, name, beta, turnover, and name-count caps one by one, and watch IR and tracking error move.

What has to be taught, in order:

  1. Name cap: 'no more than 4% in one stock.' Sector cap: 'no more than 20% in banks.' Beta cap: 'stay near the market tide.'
  2. Turnover cap: 'do not trade more than X% of the book this month.' Name count: 'hold between 40 and 80 names.'
  3. Each cap is a sentence a PM can say. Teach the sentence, then the inequality.
  4. A book that hugs the index to satisfy every cap is a closet indexer (168). Tracking error will look tiny and IR will look stable.
Trap to teach, not a footnote. Adding constraints until the book is the benchmark, then celebrating the low tracking error.

156 Cost-aware optimization and capacity

Teach this one skill: Put spread and impact in the utility, and draw net IR against assets under management.

What has to be taught, in order:

  1. Re-warm 088: turnover × spread is the first bill. Impact (064, square-root law) is the bill that grows with size.
  2. A turnover penalty is a cheaper cousin of a full impact model. Teach both; use the penalty first.
  3. Capacity is the AUM at which net IR hits your hurdle (often zero). Draw the curve.
  4. Boyd et al. 2017 as the clean modern write-up of 'return − risk − costs.'
Trap to teach, not a footnote. A paper IR with zero costs, quoted as the live number.

157 Multi-period rebalancing: when not to trade

Teach this one skill: Show that a decaying score plus today's cost says 'do not fully chase this month's list.'

What has to be taught, in order:

  1. Myopic: each month, pretend there is no tomorrow and trade to the new target. That churns.
  2. Gârleanu–Pedersen / Boyd multi-period: because the score fades and trading costs money, the right book is between last month's holdings and this month's dream book.
  3. Count the skipped trades. That count is the lesson, not a footnote.
  4. Half-life of the score (from 143) is an input to this problem, not a separate hobby.
Trap to teach, not a footnote. Rebalancing fully to the new target every month 'because the optimizer said so' while IC decay is slow and costs are not.

158 Convex optimization toolkit

Teach this one skill: Say what a QP/SOCP is, why convexity lets a solver certify a solution, and what a non-convex tweak throws away.

What has to be taught, in order:

  1. Everyday picture: you are standing in a bowl. Any local lowest point is the global lowest point. That is convex. A solver can promise it found the bottom.
  2. A quadratic program has a bowl-shaped objective and straight-line constraints. Long-only + sector caps + a quadratic risk term is a QP.
  3. SOCP: a slightly richer bowl (e.g. some impact terms). Teach when you need it.
  4. A non-convex variant (a ratio, a cardinality trick without a reformulation) cannot be certified. Show one on purpose.
  5. Boyd–Vandenberghe selected chapters; OSQP / Clarabel as the engines, not the idea.
Trap to teach, not a footnote. Calling 'we ran scipy.optimize with a random start' an optimal book.

159 Robust and resampled optimization

Teach this one skill: Perturb the scores and show naïve MVO thrashing, then compare shrinkage and a simple tilt.

What has to be taught, in order:

  1. Inputs are noisy. A 1% change in a score can flip a naïve MVO book. Teach this with a perturbation, not a speech.
  2. Resampling (Michaud): average the books from noisy inputs. Shrinkage (Ledoit–Wolf, again): calm the covariance.
  3. A simple tilt (151) is often more stable than a fancy robust program. Honesty about that is in-syllabus.
Trap to teach, not a footnote. Treating robustness as a reason to skip the QP. Robustness is a test of the QP, not a replacement for stating the utility.
